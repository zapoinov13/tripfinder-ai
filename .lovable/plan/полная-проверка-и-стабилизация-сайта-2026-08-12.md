# Полная проверка и стабилизация сайта

## Что уже проверено сейчас

- TypeScript-типизация: ошибок нет.
- ESLint: 582 замечания. Из них:
  - 561: форматирование (Prettier), на работу не влияет;
  - **10 реальных ошибок React Hooks**: хуки вызываются условно (после раннего `return`) в админ- и оператор-страницах;
  - 11 предупреждений hot-reload (косметика).
- Страницы: 33 маршрута (публичные, профиль, оператор, админ). Метаданные `head()` есть везде, кроме layout-файла профиля (это нормально).
- Ни у одного маршрута нет `errorComponent`/`notFoundComponent`: при ошибке данных страница падает целиком.

## Реальные проблемы, которые надо починить

1. **Условные хуки (риск белого экрана)**
   `admin/analytics`, `admin/audit-logs`, `admin/bookings`, `admin/operators`, `admin/payments`, `admin/tours`, `admin/users`, `operator/tours`: `useMemo` вызывается после проверки доступа. При смене состояния пользователя React выбрасывает ошибку и экран ломается. Переносим все хуки в начало компонента, проверку доступа: после них.

2. **Нет обработки ошибок маршрутов**
   Добавляем общий `errorComponent` и `notFoundComponent` (в корневом маршруте и на страницах с динамическими данными: `tour/$tourId`, `destination/$destinationId`), чтобы вместо белого экрана показывалась понятная страница с кнопкой «Назад».

3. **Единое форматирование**
   Прогоняем автоформат и авто-фиксы линтера, чтобы линт стал чистым и будущие реальные ошибки были заметны.

## Сквозная проверка всех страниц

Автоматический прогон в браузере по каждому маршруту с записью ошибок консоли и сетевых сбоев:

- Публичные: `/`, `/search`, `/destinations`, `/destination/:id`, `/hot`, `/premium`, `/compare`, `/favorites`, `/about`, `/for-operators`, `/ai-search`, `/notifications`, `/login`, `/registration`, `/tour/:id`
- Профиль: `/profile`, `/profile/favorites`, `/profile/trips`, `/profile/ai`, `/profile/settings`
- Оператор: 9 страниц кабинета
- Админ: 12 страниц панели

Для каждой страницы фиксируем: рендерится ли контент, есть ли ошибки в консоли, работают ли ключевые кнопки.

Отдельно проверяем сценарии:
- Главная → поиск → фильтры → сортировка → карточка тура → бронирование (демо-модалка)
- Избранное и сравнение (добавление/удаление, лимиты)
- Вход демо-аккаунтами (турист, премиум, оператор, админ) и доступ к соответствующим кабинетам
- Мобильный вид (нижняя навигация, фильтры в bottom sheet, sticky CTA)

## Проверка бэкенда

- Сверяем, что таблицы из миграции (`profiles`, `organizations`, `tour_offers`, `bookings`, `favorites`, `comparisons`, `price_alerts`, `notifications`, `payments`, `subscriptions`, `promotions`, `audit_logs`, `analytics_events`, `ai_searches`, `platform_config`) реально существуют, у всех включён RLS с политиками и правами доступа.
- Проверяем, что синхронизация локальных данных с базой и загрузка каталога не падают при пустых данных.
- Запускаем сканер безопасности и фиксируем критические находки.

## Результат

Отчёт списком: страница → статус (ОК / исправлено / требует решения), плюс исправленный код. Дизайн не меняем: только работоспособность.

## Технические детали

- Порядок работ: хуки → error-boundary маршрутов → автоформат → прогон Playwright по всем маршрутам с логированием → проверка БД/RLS.
- Playwright-скрипт держим во временной папке, в проект не добавляем.
- Формат отчёта: таблица: маршрут / ошибки консоли / визуальный статус.
